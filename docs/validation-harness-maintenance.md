# 検証基盤の管理と自律的な改善

検証コードの重複、検査対象からの漏れ、管理外成果物の蓄積は、ユーザーの指摘を待たず検知・対処する。ルール追加だけで改善完了とはしない。

HTML の検証は継続的な品質保証コードとして扱う。明示的な依頼を待たず、Git 管理、CI/CD、ローカルの標準チェックへ組み込む。`tmp` に置くのは生成値・実測結果などであり、検証基盤自体ではない。

## 管理境界

- 再利用する実行コード・設定スキーマ・契約テストは Git 管理し、既存の検査導線へ登録する。
- 生成設定、実測結果、必要な原本証跡、キャッシュ、私有資料は Git 管理外とする。私有資料を公開しない。
- 保持物は現行依存と必要な判断証跡で決める。不要なビルド成果物は使用中・参照・所有範囲を確認して整理する。
- 現在の概要は短い入口に集約し、過去ログは必要な証跡だけ参照する。退避領域を通常の探索へ含めない。

再生成可能なコンパイラキャッシュと、必要な成果物・使用中の出力を区別する。既存実装がキャッシュの一部を常に保持していても、それをユーザーの永久保持条件へ読み替えない。整理の対象はCargoの所有分類、全hardlinkの閉包、保護対象との非交差、sessionの形式とlock、実行前後の同一性で限定し、不明・使用中・変化したものは保持する。必要量に足りない予行結果で削除せず、既存の検証済みキャッシュ分類との結合を先に評価する。キャッシュ再生成による次回ビルドの負担と、表示速度・メモリの非劣化は別々に検証する。

CLIの診断ビルドでも、既存の `native_cli_build_bindings.base_environment` による標準環境を再利用する。実行ファイルだけ合わせ、`RUSTFLAGS=-D warnings` などの設定を親プロセス任せにしない。予行と実行のツール・引数・必要な環境を保存し、子ビルドの終了後にも固定容量を確認する。整理直後や子コマンドの終了値だけを、整理・再ビルド全体の成功にしない。

## 設計判断

既存 unittest と安全なプロセス・容量ガードを再利用する。外部入力検証、型検査、重複検知には既存ライブラリを比較し、独自実装は必要性が確認された部分に限定する。ライブラリ導入で受入基準や検査範囲を下げない。

外部API・型宣言の制約による不可避な検査指摘は、対象と理由を限定して記録し、再確認を挟まず例外を判断する。たとえばdefault exportを使う外部APIの型宣言だけを例外にできる。内部コードへの一括免除や、描画・カバレッジ・性能条件の緩和へ広げない。例外不要で正確に表現できる場合は、その実装を維持する。

新しい共通基盤の言語は既存の Rust・TypeScript 構成との整合から選び、Python を前提にしない。Python を継続利用する実行コードには、Lint と厳格な型検査を必須とし、管理外にあることを検査の免除理由にしない。コードの重複検査には対応言語を確認した既存ツールを使用する。

テストの反復コードも抽象化の対象とする。「意図的な反復」を免除理由にせず、共通処理・共通データ・パラメーター化で重複を減らす。テストを検査から除外したり、アサーションや入力観点を削って重複率だけを下げたりしない。

共通helperを複数の配置で使う場合は、実際の全consumerのmodule階層と可視性を確認する。単一の簡略fixtureでの成功を全consumerの名前解決・型検査へ代用しない。純粋probe、実コンパイル、native実行の証跡は区別する。 関数を親へ移すときは、その関数が使う型のimportも実際の宣言元から移す。親が持っていないbindingをsuperから取得できると仮定せず、元の絶対crate pathを維持できる場合は維持する。

テスト用macroの共通化では、実際の全呼び出し形について、末尾commaやstatement区切りをコンパイラの展開で確認する。rustfmtや未展開ASTの成功をmacro展開・実ライブラリの型検査と同一視しない。

静的なsource所有分類は、実binaryの由来・実行・入力改変検出を証明しない。後段の実検証を保持し、静的firstへnative buildを先行要求する循環や、同じruntimeガードの独自AST検証への重複実装を作らない。

native CLIのプロセス証跡は、固定した実行ファイル・引数・環境・開始したprocess group・物理raw出力のwriter FD・入力と結果の照合に範囲を限定する。`groupClosed`を全子孫の終了へ読み替えず、`descendantClosureProved=false`とsource endpointのみの保証を維持する。実runで観測された逃亡・残存・後書込み・終了期限超過は失敗にする。全FDを閉じて別sessionへ逃亡する負例は保持し、全tree成功へ昇格させない。

全子孫をatomicに追跡する汎用基盤を、原要求にない描画・性能検査開始の前提へ追加しない。必要なconsumerが強い終了保証を要求する場合だけ、既存OS機能・ライブラリ・必要権限を別途評価する。限定プロセス証跡の受理は、consumerの実動作、117件各99、HTML全90、性能非劣化、カバレッジ、CIの成功を意味しない。判断根拠は `tmp/quality/macos-native-process-supervision-library-assessment-r1/report.md` に保持する。

重複検査は CI とローカル標準チェックの必須ゲートにする。保守速度に影響する反復を厳格に検知する一方、短い定型表現など改善効果の低い候補は個別に根拠を記録して判断する。既存の重複を通す目的で閾値を緩めず、テスト全体の免除を設けない。

固定手順の共通化と小さな解析アダプターを優先する。大きな継承階層や全面移行は、保守負担を減らす根拠がある場合だけ採用する。

2026-10-12の実評価では、task DAGと結果・出力cacheは既存moon 2.6.1、TypeScriptの外部データ形状検証はZod 4.6.6を採用する。KRRには固定した検査設定とKRR固有の受入処理だけを置く。過去の設計報告にある汎用runner・receipt基盤の新造案を、現在の許可と解釈しない。既存基盤で実現できない機能が確認された場合は、独立ライブラリとして扱い、KRR内に汎用テスト・cache基盤を構築しない。

## ユーザー指摘と未完了の改善

指摘事項と未完了状態は `docs/quality-gate-improvement-tasks.md` の Q01–Q22・R01–R06へ集約する。本書は設計原則を保持し、別のチェックリストを重複管理しない。再開・圧縮・担当統合の際は最新指示と番号付き台帳を読み、担当終了だけで検証済みにしない。

完了済みの担当へ続行を依頼する場合は、起動を伴う `followup_task` を使う。`send_message` だけで実行中とみなさず、待機へ入る前に担当の実行状態を確認する。起動漏れを、外部待ちや検査中として記録しない。

担当開始後の競合は、開始時に保存した実ファイルと現在のファイルを直接比較して判定する。HEADとの差には継承した変更も含まれるため、開始後の追加とみなさない。Rustのテスト件数はテスト属性の付いた関数を数え、補助関数をテストに含めない。

全体検査の入力一覧を前回から引き継ぐ場合、再利用するのはパス集合だけとする。開始時hashは全入力の現在の実ファイルから新しく計算し、起動直前に実ファイルとの一致を確認する。古いpath→hashのコピーを開始時snapshotと呼ばない。不十分な開始記録と終了hashの差は実行中driftの証拠にならず、合格扱いせず別の訂正証跡を保存する。

並行担当には、コードの編集範囲に加えて、証跡の保存先も担当・責務ごとに一意な絶対パスで指定する。凍結した証跡を別担当が上書きしない。保存先の競合が見つかった場合は書込みを止め、現存内容を保持して各担当の証拠を別の保存先へ分離する。元bytesとSHAを復元できない場合はその制限を記録し、後続の再検証と区別する。

アンチパターン：検証ごとに管理外の実行コードを複製し、過去ログと成果物を無制限に積み上げる。正しい運用：管理された共通コードから値と結果だけを生成し、保持根拠のない成果物を整理する。

### Bunのファイル指定と保存証跡の分離

Bunで個別のテストファイルを実行するときは、実在するファイルを `./scripts/..._test.ts` または絶対パスで指定する。`scripts/..._test.ts` は文字列フィルターとして扱われ、tmp内の同名source snapshotまで収集し得る。保存snapshotを検査対象へ混入させず、対象ファイル数と実コマンド全体の終了値を確認する。対象テストの成功だけでsnapshot import errorsを含む失敗を合格へ読み替えない。実再現・修正証跡は `tmp/quality/rust-native-width-unused-realm-root-final-suite/receipt.json`。

重複検査の件数は保存されたJSONレポートの入力集合・統計・複製レコードから取得する。JSON-only reporterの標準出力に複製表示がないことや終了値0を、重複0の根拠にしない。実行前後の物理入力を固定し、異なるtoken/line inventoryの結果を同じ入力として比較しない。
