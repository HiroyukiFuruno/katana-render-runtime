# HTML frame artifact contract

`HtmlFrameArtifact` is a host-owned, opt-in persistence format for one rendered pixel frame. It is not a serialized browser session. The artifact contains no raw HTML, form field, password, DOM, event queue, V8 isolate, or JavaScript state. The pixel buffer can still visibly contain sensitive text rendered by the document, including form values, so hosts must treat every artifact as sensitive data and choose the storage path and retention policy explicitly.

`HtmlArtifactProvenance::for_source` computes the source SHA-256 and fixes the runtime version to the crate version. The host must provide 64-character hexadecimal SHA-256 fingerprints for render configuration, resource contents, and font contents. An empty resource or font set still requires the SHA-256 of that empty set. A missing or malformed fingerprint rejects artifact creation.

The frame artifact stores a SHA-256 digest over its generation, origin, viewport, scroll and content metrics, pixel format, and pixels. Loading or validating an artifact rejects a structurally valid JSON file whose frame data was changed after saving.

`HtmlArtifactStore::new(root, capacity_bytes, enabled)` requires explicit opt-in. With `enabled = false`, construction performs no directory creation or persistence I/O. The capacity applies to all regular files below the store root, including committed artifacts and leftover temporary files; load also refuses a file larger than the store capacity before allocating its contents. The root is canonicalized after symlink rejection, and keys cannot contain path separators. Root, artifact, temporary, and lock paths reject symbolic links. Writes use a private temporary file, flush and sync, then `std::fs::rename`. The Rust standard library uses `MoveFileExW(..., MOVEFILE_REPLACE_EXISTING)` on Windows, so an overwrite failure does not remove the old artifact. A failed write removes only the temporary file. Readers open the committed destination while writers operate on the temporary path, so a reader sees either the old complete artifact or the new complete artifact.

The root is a host-owned private directory. Artifact keys are portable file-name tokens of at most 128 ASCII letters, digits, `-`, or `_`; Windows device names are rejected. Windows builds do not change ACLs in this library, so the host must enforce equivalent private permissions. Shared or untrusted roots are outside the supported trust boundary because filesystem checks cannot eliminate all concurrent TOCTOU attacks.

Saving uses a create-new store lock and includes the writer PID. A crashed writer can leave the lock behind; before calling `recover_lock`, the host must establish that every writer using the root has stopped. Calling it while a writer is live can delete its lock and permit concurrent writes. The library never guesses that a lock is stale and never removes a live writer's lock automatically. Quota accounting and replacement are performed while this lock is held, including when multiple store instances share one root.

`HtmlFrameArtifact::resume_session` first verifies the artifact and current source provenance, then calls `HtmlRuntime::open` to create a fresh V8 runtime. Only the stored scroll position is dispatched into that new session. A frame cache hit therefore never claims that JavaScript or form state was restored; callers must exercise link, form, and JavaScript behavior against the fresh session.
